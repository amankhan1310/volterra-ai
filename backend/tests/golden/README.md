# Golden reference fixtures (`synthetic-v1`)

These JSON files are the **exact outputs of the original browser prototype** in `legacy/`.
The Python port in Phase 2 must reproduce them. They are generated by
[`legacy/tools/export_golden.js`](../../../legacy/tools/export_golden.js) and must never be
edited by hand.

## How they are produced

The exporter runs the **unmodified** `legacy/core.js` and `legacy/ui.js`, in the same order as
`legacy/index.html`, inside a Node `vm` sandbox with a minimal DOM stub. `window.echarts` is
left undefined, so the prototype takes its SVG fallback path. The exporter then reads the
prototype's own values (`D`, `F`, `BT`, `AN`, `P`, `sohNow`, `fade`) and calls the prototype's
own functions (`rng`, `lin`, `med`, `rulAt`, `rate`, `sohAt`, `eolN`, `insights`, `hcol`,
`cond`, `xt`) to export them. The legacy sources are only read, never copied or modified.

A few values are computed inline in the page renderers and have no callable function. These
are the gauge life-used fraction, simulator deltas, Charging Advisor rows and the Overview
acceleration check. For those, the exporter evaluates the same expression and cites the source
line in the fixture's `source` / `formula` fields. Built-in sanity checks abort the export if
the exporter's view ever disagrees with the prototype. They check that the recent fit equals
`F`, the backtest MAE equals `BT.mae`, and the detector's flags equal `AN`.

## Commands

```sh
# Regenerate (only when legacy/ or the exporter changes intentionally)
node legacy/tools/export_golden.js

# Verify: two independent runs are identical AND match the committed files (exit 1 if not)
node legacy/tools/export_golden.js --check

# Exporter test suite (Node's built-in runner; no npm install needed)
node --test legacy/tools/export_golden.test.js

# Export somewhere else, e.g. to diff
node legacy/tools/export_golden.js --out /tmp/golden
```

CI (`.github/workflows/golden.yml`) runs the tests and `--check` on Node 18, 20 and 22.

**When to regenerate:** only when the prototype or the exporter changes on purpose. In that
case, bump `EXPORTER_VERSION` and explain the change in the commit message. During Phase 2 the
fixtures are the specification: if the Python port disagrees, fix the port, not the fixtures.
Known defects F1–F8 are fixed in Phase 5. Each fix updates the affected fixtures in its own
commit with a changelog entry.

## Conventions

- Every fixture starts with `meta`. It contains `fixture`, `schema_version`, `description`,
  `provenance`, `source` (legacy file:line references), `units`, and, where relevant,
  `definitions`, `known_issues` and `notes`.
- Units go in key names and in `meta.units` (`_ah`, `_pct`, `_c`, `_v`, `cycles`). Cycle
  indices are 0-based.
- `null` means the same as in the prototype: for example, RUL with a non-negative slope, or
  cycles-to-EOL beyond the 5,000-cycle scan.
- **Non-finite numbers** are stored as the strings `"NaN"`, `"Infinity"` and `"-Infinity"`,
  because plain JSON cannot represent them. Python consumers should map them back with
  `float(x)`.
- Output is deterministic. It has no timestamps or machine paths, LF line endings, and keys in
  a fixed order. Arrays of scalars are written inline and wrapped every 10 values.

## Numerical guidance for the Python port (Phase 2)

Numbers are written in JavaScript's shortest round-trip form, and Python's `json` parses them
back to the identical IEEE-754 doubles.

- **Bit-exact (`==`):** PRNG values; `capacity_ah`, `soh_pct` and `voltage_v`; `lin` and `med`
  results, provided the Python code adds terms in the same order as the JavaScript; RUL;
  backtest; the voltage and capacity anomaly channels. The exceptions are values derived from
  `temp_c`: the temperature channel, the `temp_vs_soh` fit, and the temperature anomaly count
  in the insights.
- **Tolerance (`rel ≤ 1e-12`):**

  - `temp_c` and everything derived from it, because it uses `Math.sin`.
  - Simulator and advisor values, because they use `Math.exp` and `Math.pow`.

  Python's `math` module calls the platform C library, which may differ from V8 in the last
  bit. Integer outputs such as `cycles_to_eol` must still match exactly.

- Port `mulberry32` with explicit 32-bit arithmetic (`Math.imul`, `>>>`, `|0`).
